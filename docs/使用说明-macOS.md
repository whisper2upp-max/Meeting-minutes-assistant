# 使用说明（macOS）

会议纪要助手：开会时内录系统声音 + 麦克风，结束后自动"转文字（区分说话人）→ 生成会议纪要"，全程只访问阿里云百炼。

## 一、安装（就一步）

把「会议纪要助手.app」放入「应用程序」文件夹，**右键 → 打开**（首次需要，之后正常双击）。

不需要装驱动、不需要跑任何脚本——录音所需的 BlackHole 驱动已内置在 app 里，首次点录音时自动安装。

## 二、首次使用（约 30 秒）

1. 点「设置…」→ 填入百炼 API Key（**公司专属网关用户再填"API 网关"**，见百炼开通说明中的 API Host）→ 保存
2. 点红色录音按钮 → 弹出"首次使用配置" → 点「一键安装并开始录音」→ 输入一次开机密码（安装内置的录音驱动）
3. 首次录音时 macOS 会请求麦克风权限 → 允许

之后打开 app 直接用，不再有任何配置步骤。

## 三、日常使用

1. （可选）填会议标题，用标签添加本场参会人，并选择简要、标准或详细纪要
2. 加入 Teams 会议、戴好耳机后，点中间的**红色圆形按钮**开始录音
   - 程序自动处理一切：临时切换到"会议内录输出"（耳机 + 内录），录完后自动切回你的耳机
   - 换了耳机也无需重配，每次录音都按当前输出设备自动适配
3. 会议结束再点一下该按钮，自动进入"上传 → 转写 → 纪要"
4. 完成后点「查看纪要」或「打开文件夹」

输出目录（默认 `~/Documents/会议纪要/日期_标题/`）：
- `会议纪要.md` —— 最终纪要（决议/待办/风险等）
- `transcript.md` —— 带时间戳和"说话人1/2"标签的完整转写稿
- `speaker_map.json` —— 参会人候选及会后确认的说话人映射
- `session.json` —— 本场会议的标题、参会人、纪要档位和实际生成模型
- `纪要历史版本/` —— 在编辑页重新生成前自动备份的旧纪要
- `audio.wav` —— 混音后提交的音频存档

## 四、导入模式

用手机或其它工具录好音 → 点「导入音频/视频文件…」→ 后续流程完全相同。

## 五、提高纪要质量的小技巧

- 在设置中用标签维护常用参会人，录制或导入时可一键加入本场；会后可根据样例发言可视化匹配“说话人1/2”
- 简要档适合快速浏览，标准档保留背景和主要观点，详细档保留讨论脉络、分歧和决策依据；默认模型为 `qwen-flash` 时，详细档自动使用 `qwen-plus`
- 生成后可在纪要编辑页切换档位重新生成；程序复用现有转写，不再次上传音频，并先备份当前纪要
- 转写稿同音错别字难免，重要结论请对照 transcript.md 核查
- 任务中断不用怕：重新跑会自动续传（删除对应文件即可重做该步）

## 六、常见问题

| 现象 | 处理 |
|---|---|
| "音频中没有识别到语音内容" | 录音太短/无人说话/内录未生效；看日志"录音结束"是否为 2 轨 |
| 只有自己的声音 | 首次配置没完成（重装驱动）或会议软件没走系统默认输出 |
| 只有别人的声音 | 麦克风权限没给：系统设置 → 隐私与安全性 → 麦克风 |
| 录音期间音量条失效 | 多输出模式的正常现象，用耳机自身音量调节，结束录音自动恢复 |
| 驱动安装失败 | 重试一次；仍失败可手动安装：`brew install blackhole-2ch` 后重启程序 |
| 提示"未配置 API Key" | 设置里重新填写并保存 |
| 上传/转写失败 | 检查网络对 dashscope.aliyuncs.com（或公司网关）的访问 |

> 说明：录音驱动 BlackHole 为开源软件（GNU GPL），随 app 内置、不上传任何数据；装卸载可执行
> `sudo rm -rf /Library/Audio/Plug-Ins/HAL/BlackHole2ch.driver && sudo killall coreaudiod`。
